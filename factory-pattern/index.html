Factory method pattern — visual flow

Step through how smsCreator.send("Hello") actually runs, then see why the Creator is an abstract class and not an interface.

Lines of send() logic written: 1 (shared by every creator)

  


  

    
    
    
    
    
  


  
  
Why an abstract class instead of an interface?

  

    The Creator needs two things: a method every subclass must define differently (createNotification()),
    and a method that behaves exactly the same for every subclass (send()).
    An interface can only declare the first kind — it cannot hold real code. Only an abstract class can hold both.
  


  

    

      
✗ If Creator were an interface

      
interface NotificationCreator {
  createNotification(): Send;
  send(message: string): void;
}

class SmsNotificationCreator
  implements NotificationCreator {

  createNotification(): Send {
    return new Sms();
  }

  send(message: string): void {
    const n = this.createNotification();
    n.send(message);
  }
}

class EmailNotificationCreator
  implements NotificationCreator {

  createNotification(): Send {
    return new Email();
  }

  send(message: string): void {
    const n = this.createNotification();
    n.send(message);
  }
}

      

        Interfaces only declare a signature — no method body allowed. So the exact same 3-line body
        for send() has to be copy-pasted into every single creator class. Add a third
        channel (WhatsApp) and you paste it a third time.
      

    


    

      
✓ With an abstract class (what we use)

      
abstract class NotificationCreator {

  abstract createNotification(): Send;

  send(message: string): void {
    const n = this.createNotification();
    n.send(message);
  }
}

class SmsNotificationCreator
  extends NotificationCreator {

  createNotification(): Send {
    return new Sms();
  }
}

class EmailNotificationCreator
  extends NotificationCreator {

  createNotification(): Send {
    return new Email();
  }
}

      

        send() is written once, with a real body, inside the abstract class.
        Every subclass inherits it for free and only has to fill in the one thing that actually
        changes: which product to create.
      

    

  


  

    General rule: use an interface when classes only need to share a contract with zero shared code
    (e.g. Send — Sms and Email have nothing in common except a method signature). Use an
    abstract class when subclasses share some real, reusable behavior and some behavior that must
    vary — that mix of "common code + one gap to fill in" is exactly the shape the factory method pattern needs.
