1. readonly kya hota hai interactive demo

readonly ek modifier hai jo TypeScript mein kisi property pe laga dete ho taaki wo constructor ke andar sirf ek baar set ho sake — uske baad koi bhi (khud class ke andar bhi) usse dobara change nahi kar sakta.

class DebitCard {
  readonly cardNumber: string;

  constructor(cardNumber: string) {
    this.cardNumber = cardNumber; // ✅ yahan allowed hai
  }

  updateCard(newNumber: string) {
    this.cardNumber = newNumber; // ❌ Error: cannot assign to readonly property
  }
}
cardNumber = "1234 5678 9012"
🚫 TypeScript Error: Cannot assign to 'cardNumber' because it is a read-only property.
✅ Constructor ke andar set hone diya — yahi readonly ka allowed moment hai.
💡 Kyun use karte hain: card number, id, cvv jaisi values ek baar create hone ke baad kabhi change nahi honi chahiye. readonly lagane se TypeScript khud compile-time pe rok deta hai agar galti se koi baad mein value badalne ki koshish kare — bug pehle hi pakड़ liya jaata hai, runtime tak pahuchne nahi deta.

2. Concrete class kya hoti hai animated diagram

Haan, concrete class ek normal class hi hoti hai — bas naam isliye diya gaya hai taaki use abstract class ya interface se differentiate kiya ja sake. "Concrete" ka matlab hai: is class ka object seedha `new` keyword se ban sakta hai, kyunki isme har method ka pura implementation likha hua hai.

INTERFACE (blueprint only) PaymentStrategy
CONCRETE CLASS Upi
CONCRETE CLASS DebitCard

Interface / Abstract

  • Sirf contract deta hai
  • Method sirf signature — body nahi
  • new PaymentStrategy() ❌ karke object nahi bana sakte

Concrete Class

  • Poora implementation deta hai
  • Har method ki actual body likhi hoti hai
  • new Upi("id") ✅ seedha object ban jaata hai
interface PaymentStrategy {   // blueprint — abstract
  pay(amount: number): boolean;
}

class Upi implements PaymentStrategy {  // concrete — real class
  pay(amount: number): boolean {
    // actual logic yahan likhi hai
    return true;
  }
}

const p = new Upi();   // ✅ sirf concrete class se object banta hai
💡 Yaad rakhne ka trick: agar kisi class ko tum bina kisi aur cheez ke seedha new kar sakte ho aur usme har method "ready to run" hai — wo concrete class hai. Interface/abstract class sirf naam batate hai, kaam concrete class hi karti hai.
readonly = value lock after creation  ·  concrete class = normal, fully-implemented, directly-instantiable class
